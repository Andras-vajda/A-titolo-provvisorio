# Lotto C reference implementation

## Files

- `lotto.h`: public API, limits, contracts and result structures.
- `lotto.c`: machine-agnostic core, orbit closure, validation and metrics.
- `lotto_catalog.h`: catalog interface.
- `lotto_10_5_4_3.c`: deterministic `LD(10,5,4,3;7)` construction.
- `lotto_demo.c`: console client; no mathematical logic is implemented here.
- `lotto_test.c`: positive, negative, transactional and metamorphic tests.

## Construction

The catalog entry uses the Klein four-group generated by

```text
g = (0 1)(2 3)(4 5)
h = (0 2)(1 3)(6 7)
```

and three base blocks:

```text
{0,1,2,4,8}    orbit size 4
{0,2,6,7,9}    orbit size 2
{4,5,6,7,9}    orbit size 1
```

The generic closure routine develops seven distinct blocks. The independent
validator then checks all `C(10,4) = 210` targets.

## Language profile

The source uses a conservative C90 common denominator:

- no variable-length arrays;
- no declarations in `for` initializers;
- no compound literals or designated initializers;
- no `stdint.h`, `stdbool.h`, `inline` or `long long` requirement;
- no recursion;
- no dynamic allocation in the core;
- no mutable global state;
- no machine-word bit packing;
- no processor intrinsics.

The output array is modified only after successful completion of the whole
construction. A failure therefore leaves the caller-visible result unchanged.

## Expected validation fingerprint

```text
blocks                              7
targets                           210
minimum cover multiplicity          1
maximum cover multiplicity          4
minimum best intersection            3
cover histogram 1,2,3,4     84,84,35,7
pair intersections 1,2,3,4    8,4,7,2
```

The seven blocks are minimal by inclusion: deleting any one of them exposes a
four-set that is no longer represented. This property alone is not a proof
that the lotto number is seven; the extremal lower bound belongs to the
mathematical argument of the article, not to the construction routine.
